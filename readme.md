# OlConnect Manager

Панель управления, лаунчер инстансов и встроенный сервер подписок для туннелей OlConnect и OpenFlux. Один процесс админки поднимает веб-интерфейс, отдаёт публичные подписки и умеет зеркалить их на Яндекс.Диск.

TCP- и IP-трафик маскируется внутри легитимного трафика доверенных сервисов (видеоконференции WebRTC, документы Yandex Docs и Mail.ru Docs, доски и комнаты), а наружу выходит с вашего VPS.

Текущая версия: `server-v3.0.0` — сводный релиз линии 2.4.x (больше сотни выпусков сведены в один).

## Состав

| Компонент | Что делает |
|---|---|
| `olcrtc-admin` | Веб-панель на `:8443`, REST API под `/api/`, встроенный сервер подписок под `/sub/`, зеркало подписок, история состояния инстансов |
| `olcrtc` | Серверный бинарь туннеля: одна сторона канала (exit-нода на VPS) |
| `olcrtc-launcher` | Bash-обёртка: читает `/etc/olcrtc/<N>/env` (или `/etc/olcrtc/env`), переводит переменные в аргументы `olcrtc`, при необходимости обновляет и запускает `openflux` |
| `openflux` | L3-туннель через сервисы-носители, ставится отдельно из репозитория `OpenFlux-Android` |

### Куда ставится

| Путь | Назначение |
|---|---|
| `/usr/local/bin/olcrtc`, `/usr/local/bin/olcrtc-admin`, `/usr/local/bin/olcrtc-launcher` | бинари и обёртка |
| `/etc/olcrtc/env` | базовый env главного инстанса (`OLCRTC_CARRIER`, `OLCRTC_ROOM_ID`, `OLCRTC_KEY`, …) |
| `/etc/olcrtc/<N>/env` | env дополнительного инстанса `#N` |
| `/etc/olcrtc/admin.env` | env панели: порт, логин, пароль, публичный URL подписок |
| `/etc/olcrtc/key.hex`, `/etc/olcrtc/<N>/key.hex` | 256-битный ключ шифрования инстанса |
| `/etc/systemd/system/olcrtc-server@.service` | шаблонный юнит дополнительных инстансов (`olcrtc-server@N`) |
| `/etc/systemd/system/olcrtc-admin.service` | юнит панели |
| `/var/lib/olcrtc/subscriptions.db` | база подписок |
| `/var/lib/olcrtc/instance-history.json` | кольцевая история состояния инстансов (лежит рядом с базой подписок) |
| `/opt/olcrtc-wb-automation`, `/etc/olcrtc/wb-automation.json` | компоненты и конфиг WB-автоматизации |

Установка на чистый Linux (Ubuntu 20.04+, Debian 11+, Alma/Fedora):

```bash
curl -fsSL https://raw.githubusercontent.com/Oleglog/OlConnect_manager/master/server-install/olcrtc-setup.sh | sudo bash
```

После установки панель доступна на `https://<IP>:8443` — сертификат самоподписанный, исключение в браузере придётся подтвердить. Полное удаление: `server-install/olcrtc-uninstall.sh`.

## Возможности

### Инстансы

Один инстанс — одна exit-нода: сервис `olcrtc-server@N` со своим env и ключом.

- Создание, запуск, остановка, перезапуск, удаление (вместе с systemd-артефактами и записями в подписках).
- Носители: `jitsi`, `telemost`, `wbstream`, `openflux` (транспорты `vyandex`, `yandex`, `mailru`, `avito`, `cups`, `boards`, `telemost`, `bitrix24`), плюс `vp8channel` и `datachannel` для WebRTC-носителей. Несовместимые комбинации панель не предлагает.
- QR-код и ссылка `olcrtc://` для клиента, пинг цели (`/instances/<id>/ping`), настройки кодеков и лимитов, шифрование OpenFlux (AES-256-GCM) с генерацией ключа.
- Проверка занятости: перед остановкой, перезапуском и удалением панель спрашивает, сколько клиентов подключено сейчас.

### Подписки и зеркало

- Подписка — набор инстансов с коротким `slug` и публичным адресом `/sub/<slug>`.
- Сервер подписок встроен в админку и слушает loopback: в конфиге установки `OLCRTC_SUB_LISTEN=127.0.0.1:2097`, наружу его публикует Caddy по вашему домену. Порт — значение из `admin.env`, а не константа: установщик берёт свободный из списка и записывает в `OLCRTC_SUB_LISTEN`, флаг `-sub-listen` по умолчанию пустой (тогда порт эфемерный).
- Живой пример адреса: `/sub/Kgg9PSR2cS`.
- Зеркало подписок: панель выгружает JSON-бандл подписки на Яндекс.Диск и отдаёт клиенту bootstrap-ссылку с ключом. Настройки — в `admin.env` главного инстанса: `OLCRTC_SUB_MIRROR_ENABLED`, `OLCRTC_SUB_MIRROR_PROVIDER` (поддерживается только `yandex_disk`), `OLCRTC_SUB_MIRROR_YANDEX_OAUTH_TOKEN`, `OLCRTC_SUB_MIRROR_YANDEX_BASE_PATH`, `OLCRTC_SUB_MIRROR_PROXY` (SOCKS, например `socks5://127.0.0.1:40000`).
- Клиент принимает **не** plain-text `/sub`, а JSON-бандл из зеркала; `/sub/<slug>/open` — HTML-страница с параметрами зеркала для перехода в приложение.
- QR подписки собирается из URL и зеркала, при необходимости сжимается gzip и режется на multipart-части.

### История состояния

- Кольцо на 60 минут на каждый инстанс, запись раз в минуту: состояние, прирост байт, число клиентов, рестарты, отказы релея.
- Журнал юнита читается только в момент закрытия минуты, чтобы не дёргать systemd на каждом тике.
- История переживает рестарт панели: файл `instance-history.json` лежит рядом с `subscriptions.db`.
- Пустая история — нормальный случай сразу после установки: `history_complete=false`, пока кольцо не заполнится.

### Диагностика и обслуживание

- Логи сервисов из journald через панель, обновления бинарей, статус OpenFlux-ноды.
- WB-автоматизация: получение комнаты и токена через удалённый браузер (компоненты в `/opt/olcrtc-wb-automation`, API `/api/wb-automation/components`).
- Проверка Jitsi-комнаты (`/api/jitsi/check`), занятость портов, тест зеркала.

## API и авторизация

Все защищённые ручки требуют HTTP Basic:

| Переменная | Смысл |
|---|---|
| `OLCRTC_ADMIN_USER` | логин, по умолчанию `admin` |
| `OLCRTC_ADMIN_PASS` | пароль |
| `OLCRTC_ADMIN_TOKEN` | используется как **пароль**, если `OLCRTC_ADMIN_PASS` не задан (это не Bearer-схема) |
| `OLCRTC_ADMIN_PORT` | порт панели, по умолчанию `8443` |

Неудачные попытки входа ограничиваются по IP (ответ `429`).

```
POST   /api/auth/login
POST   /api/auth/change-credentials

GET    /api/instances                 список инстансов вместе с историей
GET    /api/instances/usage           активные клиенты по всем инстансам
GET|POST|DELETE /api/instances/<id>   чтение, создание, удаление
POST   /api/instances/<id>/start|stop|restart|ping
GET    /api/instances/<id>/qr

GET|POST /api/subs                    список и создание подписок
GET|POST|DELETE /api/subs/<slug>      подписка, её состав, обновление
POST   /api/subs/<slug>/mirror        синхронизировать зеркало
GET    /api/subs/export               выгрузка всех подписок

GET    /api/system/status             версия, аптайм, состояние сервисов
GET    /api/system/logs/<service>     журнал сервиса
GET|POST /api/system/domain           домен и TLS
GET|POST /api/system/subscription-url публичный URL подписок
GET    /api/system/ports              занятость портов
GET|POST /api/system/check-updates, /api/system/releases, /api/system/update
GET    /api/system/update-progress
GET|POST /api/system/openflux/status, /api/system/openflux/update
GET|POST /api/system/mirror-config, /api/system/mirror-config/test
GET    /api/wb-automation/components
GET    /api/jitsi/check

GET    /sub/<slug>, /sub/<slug>/open  публичные подписки (без пароля панели)
```

### Поля истории в `/api/instances`

```json
{
  "history": [
    { "at": 1759875600, "state": "L", "bytes": 14522, "peers": 1, "restarts": 0, "rejects": 0 }
  ],
  "history_since": 1759872000,
  "history_complete": false
}
```

- `history` — до 60 слотов по минуте, от старых к новым; `at` — начало минуты в UTC, кратно 60.
- `state` — один из кодов `L` (жив), `U` (рвётся), `P` (на пределе), `D` (мёртв), `I` (остановлен), либо `null`, если за эту минуту измерения нет. `null` отличается от нулевого трафика.
- `bytes` — прирост объёма за минуту, `null` если счётчик недоступен; `peers` — максимум клиентов в минуте; `restarts` — рестарты юнита; `rejects` — отказы релея (429).
- `history_since` — начало окна, `history_complete` — заполнено ли кольцо целиком.
- Приоритет кодов при нескольких сигналах за минуту: `D > I > U > P > L`.

## Деплой и эксплуатация

Обновление бинарей из панели или вручную: новый файл скачивается во временный каталог и ставится поверх старого через `install -m 0755`, после чего сервис перезапускается.

```bash
# вручную, если ставите сборку сами
sudo install -m 0755 olcrtc-admin /usr/local/bin/olcrtc-admin
sudo systemctl restart olcrtc-admin

sudo install -m 0755 olcrtc /usr/local/bin/olcrtc
sudo systemctl restart 'olcrtc-server@*'
```

Полезное:

```bash
journalctl -u olcrtc-admin -f           # панель
journalctl -u olcrtc-server@5 -f        # инстанс #5
systemctl list-units 'olcrtc-server@*'  # все инстансы
```

Зачем `OLCRTC_OPENFLUX_AUTO_UPDATE=false`. Лаунчер по умолчанию сам проверяет релизы `OpenFlux-Android` и обновляет `/usr/local/bin/openflux`. На управляемом стенде это ломает воспроизводимость: инстанс может подняться на другой версии, чем та, с которой сняты замеры. Ставьте `OLCRTC_OPENFLUX_AUTO_UPDATE=false` в `/etc/olcrtc/env` (или в `<N>/env`) и обновляйте ноду осознанно.

Куда пишется история: `instance-history.json` в каталоге базы подписок, по умолчанию `/var/lib/olcrtc/` (путь базы задаёт `OLCRTC_SUB_DB`). Файл обновляется раз в минуту и переписывается атомарно.

## Что не работает и почему

- **Клиент принимает только JSON-бандл из зеркала.** Plain-text `/sub/<slug>` остаётся для браузера и отладки: формат `olcrtc-sub` с ключом зеркала — единственный, который разбирает мобильное приложение. Если зеркало выключено, приложение подписку не получит.
- **`videochannel` и `seichannel` непригодны.** На проекте они мертвы, `datachannel` работает только с Jitsi. Панель предлагает только рабочие комбинации носитель/транспорт, остальные не показываются.
- **Капча.** SmartCaptcha обходится на стороне exit-ноды (`OpenFlux-Android`), в панели нет ни переменной, ни переключателя для этого: единственный доступный рычаг — выбор носителя и транспорта.
- **История не переживает переустановку.** Кольцо живёт в файле рядом с базой подписок; при полном удалении (`olcrtc-uninstall.sh`) он стирается вместе с `/var/lib/olcrtc`.
- **Латентности в API нет.** Панель показывает объём, клиентов, uptime, разрывы и отказы; собственного измерения задержки у неё нет, пинг доступен отдельной ручкой.
- **Дизайн-эксперимент откатан.** Переработка интерфейса («Рейка») жила в ветке `experimental/design-rail-2026-11`, её макеты лежат в `C:\Projects\ofx-design`; в master вернулась прежняя панель. Это эксперимент, а не текущее состояние.

## Три репозитория

| Репозиторий | Роль |
|---|---|
| `OlConnect_manager` (этот) | панель, лаунчер, сервер подписок, зеркало, история |
| `OpenFlux-Android` | exit-нода `openflux` на VPS и сам транспортный слой: то, чем инстанс ходит через носители |
| `OlConnect_client` | Android-клиент: профили, подписки, подключение, статистика |

Панель управляет инстансами на VPS, клиент получает профиль по QR или подписке, exit-нода выводит трафик в интернет. Версии независимы: панель не требует конкретной версии клиента, но формат подписки (`olcrtc-sub` v2) и формат зеркала общий для всех трёх.
